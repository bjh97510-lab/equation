# Google Sheets 연결 방법 (교사용)

학생들의 학습 기록을 선생님의 Google Sheets 에 저장하려면 **Google Apps Script 웹 앱**을 한 번만 배포하면 됩니다.
브라우저(학생 기기)에는 비밀번호나 API 키가 전혀 들어가지 않고, 웹 앱 URL 만 사용합니다.

소요 시간: 약 10분

---

## 1. 스프레드시트 만들기

1. [sheets.new](https://sheets.new) 로 새 스프레드시트를 만듭니다. 이름 예: `방정식 도토리 탐험대 기록`
2. 메뉴 **확장 프로그램 → Apps Script** 를 클릭합니다. (스프레드시트에 "바인딩"된 스크립트가 열립니다)

## 2. 스크립트 붙여넣기

1. 열린 편집기의 `Code.gs` 내용을 모두 지우고, 이 프로젝트의 **`apps-script/Code.gs`** 파일 내용을 전부 붙여넣습니다.
2. 💾 저장 (Ctrl+S). 프로젝트 이름은 아무거나 괜찮습니다.

## 3. 시트 자동 생성 (1회)

1. 편집기 상단의 함수 선택 상자에서 **`setupSheets`** 를 고르고 **실행 ▶** 을 누릅니다.
2. 처음 실행하면 권한 요청 창이 뜹니다. **권한 검토 → 계정 선택 → 고급 → (프로젝트 이름)(으)로 이동 → 허용** 을 누릅니다.
3. 스프레드시트로 돌아가면 다음 5개 시트와 헤더가 만들어져 있습니다.

| 시트 | 내용 |
|---|---|
| Students | 학생 기본정보, 도토리, 도장, 누적 통계 (학생당 1행) |
| LearningLog | 문제 제출 1건당 1행 (문제 내용·답·정오·힌트 단계·보상) |
| Rewards | 도토리/도장 지급 내역 |
| Progress | 학생 × 단원 × 개념별 진도와 정답률 |
| WrongAnswers | 오답노트 (학생 × 문제, 복습 상태 포함) |

## 4. 교사 키 설정 (1회)

교사용 대시보드(`#/teacher`)에 들어갈 때 쓰는 비밀 키입니다.

1. `Code.gs` 에서 `setTeacherKey` 함수 안의 `'change-me-teacher-key'` 를 원하는 키로 바꿉니다. (예: `'hongsan-math-2026'`)
2. 함수 선택 상자에서 **`setTeacherKey`** 를 고르고 **실행 ▶**. (스크립트 속성에 저장되며 코드에는 남지 않아도 됩니다. 실행 후 코드의 값을 다시 지워도 좋습니다.)

## 5. 웹 앱으로 배포

1. 오른쪽 위 **배포 → 새 배포** 클릭
2. ⚙️ 유형 선택 → **웹 앱**
3. 설정
   - 설명: 아무거나
   - **실행 사용자: 나(본인 계정)**
   - **액세스 권한이 있는 사용자: 모든 사용자**
4. **배포** → 권한 승인 → 표시되는 **웹 앱 URL** 복사 (`https://script.google.com/macros/s/.../exec`)

> ⚠️ 코드를 수정한 뒤에는 **배포 → 배포 관리 → ✏️ → 버전: 새 버전 → 배포** 를 해야 변경이 반영됩니다. URL 은 그대로 유지됩니다.

## 6. 웹앱에 URL 연결

프로젝트 루트에 `.env` 파일을 만들고 (또는 `.env.example` 복사):

```
VITE_GOOGLE_SCRIPT_URL=https://script.google.com/macros/s/여기에_복사한_ID/exec
```

또는 `src/config/appConfig.js` 의 `GOOGLE_SCRIPT_URL` 에 직접 넣어도 됩니다.

그다음 다시 빌드합니다.

```
npm run build
```

로그인 화면 하단에 "학습 기록은 선생님의 Google Sheets 에 저장됩니다." 가 보이면 연결된 것입니다.
(URL 이 비어 있으면 "체험 모드: 기록이 이 기기에만 저장됩니다." 로 표시됩니다.)

## 7. 연결 확인

브라우저 주소창에 `웹앱URL?action=ping` 을 입력하면 아래와 같이 나와야 합니다.

```json
{"ok":true,"mode":"sheets","time":"..."}
```

테스트 계정(테스트중학교 2학년 1반 1번 테스트학생)으로 로그인하고 문제를 한 개 풀면 `Students`, `LearningLog`, `Progress` 시트에 행이 생깁니다.
테스트 계정은 `Students.isTest` 열이 `TRUE` 로 표시되어 실제 학생과 구분됩니다.

---

## 8. 테스트 데이터 정리 (수업 시작 전 1회 권장)

개발·점검 과정에서 테스트 계정(테스트중학교)과 자동 테스트가 남긴 임시 행(`Q1`, `Q2` 등)이 시트에 있을 수 있습니다.
Apps Script 편집기에서 **`cleanupTestData`** 함수를 선택해 **실행 ▶** 하면 `isTest` 가 TRUE 인 학생과 임시 ID 의 행이 5개 시트에서 모두 삭제됩니다.

## 9. Code.gs 를 새로 받았을 때 (재배포)

`apps-script/Code.gs` 가 갱신되면 (예: 재전송 중복 차단용 `check` 액션 추가) 편집기에 다시 붙여넣고
**배포 → 배포 관리 → ✏️ → 버전: 새 버전 → 배포** 를 해야 반영됩니다. URL 은 바뀌지 않으므로 웹앱은 다시 빌드할 필요가 없습니다.

---

## 데이터가 저장되는 시점

- 로그인 (Students 갱신)
- 문제 제출 (LearningLog, Progress, Students) — 오답이면 WrongAnswers, 정답·보상이면 Rewards
- 개념 STEP 완료 / 개념 확인 완료 (Progress, 보상 시 Rewards)
- 오답 복습 완료 (WrongAnswers)

모든 클릭을 저장하지는 않습니다.

## 오프라인 / 저장 실패 시

- 저장 이벤트는 먼저 기기(localStorage)의 대기열에 기록되고, 15초마다 또는 인터넷 재연결 시 자동 재전송됩니다.
- 화면 상단에 "⏳ 저장 대기 N" 이 보이면 아직 전송되지 않은 기록이 있다는 뜻이며, 학생은 계속 학습할 수 있습니다.
- `LearningLog.logId` 로 중복 저장을 막으므로 같은 제출이 두 번 저장되지 않습니다.

## 오류가 날 때 확인할 것

| 증상 | 확인 |
|---|---|
| 로그인 후 "⏳ 저장 대기" 가 줄지 않음 | 웹 앱 URL 이 `/exec` 로 끝나는지, 배포 액세스가 "모든 사용자"인지 |
| `?action=ping` 이 로그인 화면으로 이동 | 배포 설정에서 "액세스 권한: 모든 사용자" 가 아님 |
| 시트에 열이 어긋남 | 헤더 행을 직접 수정하지 마세요. 잘못되었으면 시트를 지우고 `setupSheets` 재실행 |
| 교사 대시보드 "교사 키가 올바르지 않습니다" | `setTeacherKey` 를 실행했는지, 새 배포로 반영했는지 |
| 코드 수정 후 반영 안 됨 | 배포 관리 → 새 버전으로 재배포 |
| 권한 오류 (Exception: You do not have permission) | 실행 사용자가 "나" 인지, 시트 소유자 계정으로 배포했는지 |

## 개인정보 보호

- 학생 식별자는 `학교_학년_반_번호` 이며 이름은 식별에 쓰지 않습니다.
- 학생 화면은 로그인한 학생의 기록만 보여 주며, 다른 학생의 ID 를 URL 에 넣어 열람하는 경로가 없습니다.
- 전체 학생 데이터는 교사 키를 아는 사람만 조회할 수 있습니다. 키는 주기적으로 바꾸는 것을 권장합니다.
- 스프레드시트 자체의 공유 설정은 "제한됨(본인만)" 으로 두세요. 웹 앱은 선생님 계정 권한으로 실행되므로 학생에게 시트를 공유할 필요가 없습니다.
